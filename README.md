# PhCraft Ban Archive

PhCraft 公共处罚档案库，用于保存经管理员核实的严重违规案件及其公开证据。

本仓库的目的很简单：让处罚有据可查，让其他服务器在做联 Ban 或信誉判断时能够看到原始依据，而不是只看到一个玩家名和一句“已封禁”。

本仓库不是公开羞辱名单。我们只记录与服务器管理、安全和玩家财产直接相关的信息，并尽量减少无关个人信息的公开。

## 如何查阅案件

案件按年份和编号存放：

```text
cases/
└─ 2026/
   └─ PCB-2026-001/
      ├─ README.md
      ├─ case.json
      ├─ evidence/
      └─ hashes.txt
```

`README.md` 面向人工查阅，说明事件经过、证据和管理员结论；`case.json` 提供稳定的结构化数据，供联 Ban 系统或其他工具读取。

案件编号格式为 `PCB-YYYY-NNN`，例如 `PCB-2026-001`。

## 收录范围

本仓库主要收录已经核实、且有必要长期留档的严重违规，例如：

- 恶意破坏建筑、地形或公共设施；
- 盗取玩家容器中的物品；
- 使用作弊客户端、X-Ray 或战斗作弊；
- 利用漏洞获取明显不当利益；
- 规避既有封禁；
- 对服务器、后台或基础设施实施攻击；
- 其他足以造成明显损失或安全风险的行为。

普通争执、轻微刷屏、短期管理处罚等情况通常不进入公开档案。

调查中的案件不会先放到公开仓库。公开档案应当至少达到“证据能够支持管理员结论”的标准。

## 一份案件应包含什么

每个案件至少包含：

- 玩家当时使用的名称和 Minecraft UUID；
- 事件发生时间及明确的时区；
- 事件摘要；
- 违规类型和本服处理结果；
- 能够支持结论的证据；
- `case.json` 结构化记录；
- 公开证据文件的 SHA-256 摘要。

证据优先使用服务器能够直接产生或核验的记录，例如 CoreProtect 查询结果、服务器日志和管理插件记录。截图、视频和玩家陈述可以作为补充，但不应在缺少上下文时单独承担关键结论。

完整要求见 [POLICY.md](POLICY.md)。

## 案件状态

公开仓库只使用以下状态：

- `confirmed`：现有证据足以支持案件结论；
- `overturned`：后续复核或申诉推翻了原结论。

被推翻的案件不会直接删除。仓库会保留更正记录和 Git 历史，使外部查阅者能够看到结论是如何变化的。

## 玩家身份

Minecraft UUID 是本仓库用于识别账号的主要标识。玩家名称只表示事件发生时或记录建立时使用的名称，因为名称可以更改。

不要根据相似昵称、社交账号或其他无法可靠对应到 Minecraft UUID 的信息认定为同一玩家。

## 隐私与脱敏

公开证据不得包含与案件判断无关的敏感信息，包括但不限于：

- IP 地址；
- QQ、微信、邮箱、手机号等联系方式；
- 登录令牌、Cookie、API Key、数据库凭据；
- 后台地址和其他服务器安全信息；
- 与案件无关玩家的个人信息。

若精确坐标会暴露仍在使用的基地、设施或其他玩家资产，公开副本应对坐标进行脱敏。管理员可以在非公开环境中保留完整原始证据。

## 联 Ban 与机器读取

联 Ban 系统可以读取案件目录中的 `case.json`。字段定义见 [`schemas/case.schema.json`](schemas/case.schema.json)。

本仓库提供的是 PhCraft 的证据和管理结论，不要求其他服务器采用相同处罚。其他服务器应按照自己的规则评估案件，并尽可能保留到原案件页面的链接，方便后续复核或确认案件是否已被推翻。

允许的机器读取和引用范围见 [LICENSE](LICENSE)。公开证据文件不因此获得转载授权。

## 申诉与更正

当事玩家或发现事实错误的人，可以在本仓库创建 Issue，选择“案件申诉 / 更正”模板，并提供：

- 案件编号；
- 需要更正或申诉的具体内容；
- 能够支持主张的证据或可核验信息。

请不要在公开 Issue 中提交 IP、联系方式、账号凭据或其他敏感信息。如果材料不适合公开，请先说明情况，由管理员决定后续提交方式。

## 证据完整性

公开证据应尽量保留原始导出内容，并通过 `hashes.txt` 记录 SHA-256。发布后发现遗漏时，优先新增证据或提交更正，不应静默替换已经公开的事实记录。

Git 提交历史也是档案的一部分。重要更正应在案件页面中明确说明。
